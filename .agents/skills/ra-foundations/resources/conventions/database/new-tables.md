# New tables

A new table follows one checklist, so every table looks the same.

## Rule

- Plural name for entities (see [table naming](table-naming.md)).
- `id UUID NOT NULL`, generated by the application, with `CONSTRAINT pk__<table> PRIMARY KEY (id)`.
- `created_at` and `updated_at` as `TIMESTAMPTZ NOT NULL`, stored in UTC.
- Every column `NOT NULL` unless the business allows it to be absent.
- Strings as `TEXT` with named `CHECK` constraints instead of `VARCHAR(n)`.
- Named constraints: `pk__<table>`, `fk__<table>__<referenced>`, `uq__<table>__<field>`, `chk__<table>__<field>__<rule>`.
- Created in a [versioned migration](migrations.md).

## Why

- Named constraints turn database errors into messages that say which rule failed.
- The same columns and types everywhere remove a decision from every review.

## Good

```sql
CREATE TABLE articles (
    id UUID NOT NULL,
    headline TEXT NOT NULL
        CONSTRAINT chk__articles__headline__max_length CHECK (length(headline) <= 500),
    source TEXT NOT NULL,
    language TEXT NOT NULL
        CONSTRAINT chk__articles__language__iso_639_1 CHECK (language ~ '^[a-z]{2}$'),
    published_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL,
    CONSTRAINT pk__articles PRIMARY KEY (id)
);
```

## Bad

```sql
CREATE TABLE article (
    id SERIAL PRIMARY KEY,
    headline VARCHAR(500),
    language CHAR(2),
    published_at TIMESTAMP
);
```

- Singular name, `SERIAL` id generated by the database, nullable required fields, `VARCHAR`/`CHAR`, `TIMESTAMP` without time zone, no timestamps, unnamed constraints.
